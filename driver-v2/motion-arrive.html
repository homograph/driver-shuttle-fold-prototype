한눈에

탭 한 번에 두 카드가 동시에 움직인다. 나가는 카드는 높이가 접히면서 같이 작아지고, 들어오는 카드는 바로 아래 목록 행의 크기에서 출발해 카드 크기로 자란다. 같은 구간에서 동시에 돌기 때문에 “사라진 뒤 나타난다”가 아니라 자리를 넘겨받는 것으로 읽힌다.

기준점 (transform origin)

  • 두 카드 모두 상단 중앙 — TransformOrigin(0.5f, 0f). 높이가 위에서부터 자라고 접히므로 축을 맞춰야 배율과 클리핑이 같은 방향으로 간다.
  • 장소 이름은 왼쪽 중앙 — TransformOrigin(0f, 0.5f). 글자가 왼쪽 정렬이라 왼쪽 끝이 고정돼야 자연스럽다.
Rationale · 왜

설계 근거

값만 옮기면 재현이 안 되는 부분들이다. 전부 실제로 틀렸다가 고친 것이다.

나가는 카드의 배율만 다른 이징을 쓴다

알파가 .62D에 끝나는데 배율까지 Standard로 두면, 사라질 때까지 4%밖에 안 줄어 축소가 눈에 들어오지 않는다. 배율만 앞당겨 아직 보이는 동안 줄어들게 한다.

들어오는 카드의 배율은 높이와 같은 이징을 쓴다

반대로 여기서 앞당기는(스프링) 커브를 쓰면 높이가 절반일 때 배율은 이미 0.99라 성장감이 사라진다. 높이와 묶어 끝까지 같이 커지게 한다.

높이는 두 카드 모두 같은 이징(Standard)을 유지할 것. 배율은 레이아웃에 관여하지 않으니 커브가 달라도 되지만, 높이가 어긋나면 한쪽이 남긴 자리를 다른 쪽이 못 따라가 목록 전체가 출렁인다.

높이를 직접 애니메이션한다

max-height(Compose로는 넉넉히 잡은 heightIn)로 대신하면 실제 높이와 어긋나는 구간이 생겨 급가속처럼 보인다. 실제 높이를 재서 애니메이션한다.

간격은 나가는 카드가 데려간다

카드와 목록 사이 8dp 간격을 Arrangement.spacedBy로 주면 카드 높이가 0이 돼도 간격은 남아 8dp 구멍이 생긴다. 나가는 카드의 하단 padding으로 넣어 높이와 함께 사라지게 한다.

이름의 시작 배율은 계산값이다

0.714 = 목록 행 이름 20dp ÷ 카드 이름 28dp. 들어오는 카드의 이름이 바로 아래 행의 글자 크기에서 정확히 이어지도록 하는 값이다. 타이포 스케일이 바뀌면 이 값도 같이 바꿔야 한다 — 실제로 카드 이름이 26→28dp로 바뀐 뒤 0.769가 남아 있어 글자가 튀며 시작했다.

다만 이쪽은 화면 단위 재구성이다

도착 완료는 카드 하나가 카드 하나로 바뀌는 국소 변화지만, 운행 시작은 시트가 통째로 재구성된다 — 완료된 출발 행이 접히고, 요청사항 블록이 접히고, 하단 운행 시작하기 버튼이 사라지고, 시트 높이가 줄고, 헤더에 전체 보기가, 지도에 결제 버블이 생긴다.

카드만 855ms 로 늘리면 안 된다. 같이 도는 요소들이 원래 260–500ms 라, 카드만 늘리면 나머지가 다 끝난 뒤에도 카드만 355ms 더 자란다 — 늘어지고 따로 논다. 전체를 같은 시간축에 올려 기존 비율을 유지한 채 같은 배수로 늘린다.

Android · 참고 구현

Compose 구현

선형 진행도 하나를 돌리고, 속성마다 이징을 직접 적용하는 방식을 권한다. 속성별로 animate*AsState를 따로 걸면 재조합 시점이 달라 미세하게 어긋나는데, 이 모프는 두 카드의 높이가 프레임 단위로 합이 맞아야 목록이 안 출렁인다.

ArriveMorphSpec.kt상수
// 속도를 바꿀 일이 생기면 D 하나만 — 나머지는 전부 D 의 비율이다.
const val D = 855                 // 모프 본체
const val CONFIRM_BEAT = 90       // 탭 인지용 대기 (버튼은 그대로 둔다)
const val SETTLE_TAIL = 80        // 트랜지션 종료 후 목록 재구성까지

val Standard  = FastOutSlowInEasing                       // = cubic-bezier(.4, 0, .2, 1)
val ExitScale = CubicBezierEasing(.25f, .9f, .35f, 1f)
val Ease      = CubicBezierEasing(.25f, .1f, .25f, 1f)  // CSS 기본 ease (알파·색)

// 카드 상단 보더는 INSIDE stroke 라 카드 총높이에 더해지지 않는다.
val CardHeight = 204.dp
val RowHeight  = 60.dp
val CardGap    = 8.dp
ArriveMorph.ktCompose
/**
 * 완료한 카드가 작아지며 물러나고, 아래 행이 커지며 그 자리를 채운다.
 * 두 카드를 한 Column 슬롯에 함께 두고 선형 진행도(p)에서 값을 뽑아 쓴다.
 */
@Composable
fun ArriveMorph(
    completed: Stop,
    next: Stop,
    onSettled: () -> Unit,          // 여기서 목록을 실제로 재구성한다
) {
    val p = remember { Animatable(0f) }
    val reduceMotion = rememberReduceMotion()

    LaunchedEffect(completed.id) {
        if (reduceMotion) { delay(140); onSettled(); return@LaunchedEffect }
        delay(CONFIRM_BEAT.toLong())
        // 진행도는 '선형'으로 돌린다 — 커브는 각 속성이 자기 몫을 따로 적용한다.
        p.animateTo(1f, tween(D, easing = LinearEasing))
        delay(SETTLE_TAIL.toLong())
        onSettled()
    }

    // ms 기준으로 구간(지속·지연)을 잘라 이징을 먹인다.
    fun seg(easing: Easing, durMs: Int, delayMs: Int = 0): Float {
        val t = (p.value * D - delayMs) / durMs
        return easing.transform(t.coerceIn(0f, 1f))
    }

    val outT   = seg(Standard,  D)
    val outS   = seg(ExitScale, D)
    val outA   = seg(Ease, (D * .62f).toInt())
    val inT    = seg(Standard,  D)
    val inTint = seg(Ease, (D * .7f).toInt())
    val addrA  = seg(Ease, (D * .5f).toInt(), (D * .25f).toInt())
    val btnA   = seg(Ease, (D * .5f).toInt(), (D * .35f).toInt())

    Column {
        // ── 나가는 카드 ─────────────────────────────────────────────
        // 간격을 spacedBy 로 주면 높이가 0이 돼도 8dp 구멍이 남는다 →
        // 나가는 카드의 '하단 padding' 으로 넣어 높이와 함께 사라지게 한다.
        Box(
            Modifier
                .height(lerp(CardHeight + CardGap, 0.dp, outT))
                .graphicsLayer {
                    scaleX = lerp(1f, .84f, outS)
                    scaleY = scaleX
                    alpha = 1f - outA
                    transformOrigin = TransformOrigin(.5f, 0f)   // 상단 중앙
                }
                .clipToBounds()                                    // = overflow:hidden
        ) { StopCard(completed) }

        // ── 들어오는 카드 ───────────────────────────────────────────
        Box(
            Modifier
                .height(lerp(RowHeight, CardHeight, inT))
                .graphicsLayer {
                    scaleX = lerp(.92f, 1f, inT)      // 높이와 같은 이징 — 앞당기지 말 것
                    scaleY = scaleX
                    transformOrigin = TransformOrigin(.5f, 0f)
                }
                .clipToBounds()
        ) {
            StopCard(
                stop = next,
                topBorder = Navy700.copy(alpha = inTint),
                // 0.714 = 행 이름 20dp ÷ 카드 이름 28dp. 타이포가 바뀌면 같이 바꿀 것.
                nameScale = lerp(.714f, 1f, inT),
                nameOrigin = TransformOrigin(0f, .5f),   // 왼쪽 중앙
                nameColor = lerp(TextDim, Color.White, inTint),
                addressAlpha = addrA,
                ctaAlpha = btnA,
            )
        }
    }
}
재진입 차단. 모프가 도는 1,025ms 동안 도착 완료 버튼은 눌려도 무시해야 한다. 연타하면 두 단계를 건너뛰거나 카드가 두 장 남는다. 프로토타입은 S.busy 플래그로 막고, onSettled()에서 해제한다.
Feedback · 토스트

토스트

모프는 “다음 목적지로 넘어갔다”를 표현하지만 “이 경유지가 완료로 기록됐다”는 화면 어디에도 남지 않는다 — 완료된 곳은 목록에서 빠지고, 확인하려면 전체 보기로 들어가야 한다. 그래서 토스트로 못을 박는다.

  • 문구 — 경유지 도착 완료 처리됨
  • 시점 — 버튼을 누른 즉시. 모프가 끝난 뒤가 아니다. 운전 중에는 탭하고 도로를 본 뒤 돌아오므로, 확인은 동작보다 오래 남아야 한다.
  • 위치 — 스크린 하단 20dp. 다만 하단에 전폭 CTA(운행 시작하기·결제하기)가 있는 화면에서는 버튼을 통째로 덮으므로 그 버튼 위 20dp로 비껴간다.
  • 지속 — 1,700ms 표시 + 260ms 페이드아웃. 모프(1,025ms)보다 오래 남는다.

// 탭 즉시. onSettled() 가 아니라 onClick 안에서 부른다.
onArriveClick = {

A11y · 접근성

접근성

  • 모션 감소 — 켜져 있으면 모프를 돌리지 않고 140ms 뒤 즉시 전환한다. 토스트는 그대로 띄운다(모션이 없을수록 확인이 더 필요하다).
  • 완전히 없애지는 않는다 — 140ms 는 탭이 인지될 최소한이다. 0으로 두면 목록이 순간이동한 것처럼 보인다.
  • 스크린리더 — 모프는 장식이다. 목록 재구성 시점에 “경유지 도착 완료 처리됨. 다음 목적지 ○○○”를 liveRegion으로 한 번만 알린다. 애니메이션 중간 상태는 읽히지 않게 한다.
ReduceMotion.ktAndroid
// 시스템 '애니메이션 배율'이 0이면 모션 감소로 본다.
@Composable
fun rememberReduceMotion(): Boolean {
    val resolver = LocalContext.current.contentResolver
    return remember {
        Settings.Global.getFloat(
            resolver, Settings.Global.ANIMATOR_DURATION_SCALE, 1f
        ) == 0f
    }
}
Pitfalls · 흔한 실수

흔한 실수

이 모프를 만들면서 실제로 밟은 것들이다.

증상원인고치는 법
